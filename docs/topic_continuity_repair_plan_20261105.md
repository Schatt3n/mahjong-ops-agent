# 通用话题切换与审查修复计划

## 已确认的产品行为

用户委托组局后，可以继续聊生活、工作、技术或其他话题。主 Agent 根据完整原话、引用和上下文理解当前话题，不按话题关键词树分流。非业务交流不撤销原委托、修改既有条件或确认参加；原任务继续按原授权推进。没有与客户相关的真实局况变化、也没有客户主动询问时，不追加局况、招揽或引导回打牌的尾句。真实变化的通知仍须经过已有授权、渠道、隐私和幂等边界。

用户同时表达业务变更时，仍需识别变更并通过合法工具执行。例如聊天中说晚点才能来、退出或修改同桌限制，不能因整轮属于闲聊而忽略。自然语言关系由模型理解，后端保障状态与执行边界。

## 根因及职责

1. **合同冲突**：主提示禁止闲聊回流业务，却提供转回打牌的旧示例；话术审查与末端过滤把普通技术名词当成实现泄露。修复主提示、审查、末端规则和非业务入口的一致性，不添加生活/工作/技术场景的业务 if-else。
2. **任务及上下文保持**：验证插入新话题后原 game、当前任务事实、委托及待办保持；再次提问能使用权威状态。只在有可复现缺口时修改任务或上下文服务，不向主循环添加场景分支。
3. **审查输入与配置**：发送副本精确去重，完整有序工具证据只保留一份，最新反馈与重复合同用可核验引用。建立生产、模拟及评测共用的独立审查配置；主模型保持原配置，审查默认 enabled/low、16384 输出上限、独立 180 秒总预算，允许显式配置且记录实际请求。租约覆盖更长审查，避免恢复调度重复执行。
4. **测试及证据合同**：固定审查文本逐例显式声明 objective_status，纯告知与征询各自匹配，保留状态错配负例。完整可见可用池为空且 supports_narrower_empty_claim=true 时，接受有来源的更窄空结论；非空、截断、失败或没有证明时不得扩张结论。保留旧资产和失败报告，产品政策以追加修订记录绑定原来源哈希。
5. **精确时长能力**：声明并真正执行 max_duration_hours 等结构化时长限制。已知超上限的局不得判为符合；未知时长和系统生命周期默认值不得冒充客户约定时长。Memory/SQLite 共用领域比较，查询仍无业务副作用，证据只声明真正执行的约束。
6. **动作归属**：工作/生活讨论中的“用户已经发邮件”等表达，不能仅因“发了/问了”裸词而判为 Agent 虚构外联。使用同一次独立审查的结构化归属和来源证据，并由后端核验当前文本及同客户原话；不按话题标签或主语关键词豁免。Agent 自称已执行的动作仍需真实工具/持久证据。

## 实施顺序与验收

1. 固化政策、源资产及测试矩阵，新增或修订受影响用例后先执行这些用例。
2. 并行修改合同/过滤、审查传输配置、评测夹具及领域时长比较，所有写入保持 Store/ToolGateway 边界。
3. 先跑对应离线正反例，再用当前目标模型回放受影响的失败例和相邻反例；每次写新证据目录，有效失败不重抽答案刷分。
4. 受影响范围通过后，运行全部 pytest、默认离线评测、中文注释和 diff 检查。
5. 冻结最终代码、模型配置和评测资产，在同一次 --full 运行中执行全部必需范围；默认首个失败范围停止，未运行范围单列。不得拼接旧成绩。

## 明确测试矩阵

| 编号 | 场景 | 必须验证的结果 |
| --- | --- | --- |
| T01 | 组局后讨论生活、工作、技术及未预置的新话题 | 回复跟随当前话题；无硬带局、额外招募和无依据提醒；原业务状态保持 |
| T02 | 非业务话题插入后再问“现在几个人了” | 读取原局最新真实状态，不重建、不撤销、不重新问已知条件 |
| T03 | 尚未完成的委托中插入闲聊，再补必要条件 | 原授权及已确认事实仍可用，完成原目标，不重复征询原委托 |
| T04 | 闲聊中同时明确晚到、改时间或退出 | 更新真正变化的业务事实；无关话题不进入组局条件 |
| T05 | 引用生活/技术句子的更正 | 结合引用理解；不解释为入局确认或修改原局，不强制复述原词 |
| T06 | 原局人数、开场安排或取消等真实变化 | 仅相关真实变化可触发已有通知路径；权限关闭/其他客户/重复事件均不越界或重复外发 |
| T07 | 局况未变的重复闲聊、单纯时间流逝、后台计划变化 | 不虚构进展、不反复播报旧局况、不冒充已联系 |
| T08 | 普通技术/办公术语与真实敏感信息对照 | 普通概念不误杀；凭证、专用内部字段、未授权身份和混淆绕过仍阻断，规则不回显秘密 |
| R01 | 纯告知 completed / 真实征询 waiting_user | 正确组合通过；同文本状态错配拒绝；标签及期望不进入模型 |
| R02 | 审查重复工具结果、重复/不同版本合同、失败历史 | 解引用后事实、类型、顺序和失败历史与原证据一致；原对象及原 trace 不变 |
| R03 | 审查配置默认、覆盖、非法值、实际请求和预算 | 生产和评测共用配置；主配置不变；独立预算与租约生效；超时未形成判决不得算通过 |
| R04 | 用户真实工作动作 / Agent虚构已外联 / 借其他来源 | 同客户原话支持的其他主体动作可自然讨论；伪造来源、改文本、借别的客户或Agent无执行证据仍拒绝 |
| E01 | 完整空池证明且约束已保留 / 无证明的空返回 | 前者可支持更窄空结论；后者及非空、截断、失败结果不能冒充证明 |
| D01 | 4 小时与 5 小时局、边界值、时长未知 | 最大 4 小时约束真正执行；未知不冒充符合，系统默认时长不等于约定 |
| D02 | 时长过滤、容量和其他条件混合，SQLite 重开 | 双存储结果一致，无状态/邀约/外发副作用；applied_filter_fields 与真实执行相符 |
| S01 | 前置参数错误安全恢复与有副作用反例 | 保留既有恢复证明、独立计数、业务/权限/隐私硬断言 |
