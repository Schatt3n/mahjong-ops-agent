# AgentWechat 实验日记

## 2026-11-13 · 从扫码到无界面收发

目标是让麻将馆 Agent 通过自有设备上的 Hub 接收消息、定位联系人和发送回复。桌面主要用于登录、查看状态和人工接管。GeWe、FastBridge 等其他方案的早期对比见 [微信接入试验记录](wechat_channel_trials_20261113.md)。

| 尝试 | 证据与结论 |
| --- | --- |
| Apple Silicon 上启动、扫码和重启 | 真实账号完成扫码，桌面应用与本地 Hub 能重启并恢复。部分新构建触发 macOS 钥匙串授权，仍要验证长期签名和无感升级。 |
| 不操作桌面直接收发 | 从真实 Hub 读取到入站文字。按昵称唯一匹配后提交过一条真实私聊，微信返回接收回执。收件手机上的到达时间、真实普通群双向闭环和长期在线待测。 |
| 联系人备注 | 有一个真实联系人可以按昵称找到，备注却为空。保留的增量回包里有带版本控制的备注，Hub 跳过了该字段。按 ID 单独刷新后，备注成功写入本地；回包中的备注和当时搜索的全名不同。另一次检查发现 44 个通讯录批次未完整落库，已识别卡点主要在群资料，不能据此统计缺少的好友数。 |
| emoji 和表情包 | 模拟环境通过事件流读取到 Unicode emoji 和微信文字表情标记，并下载了表情包 GIF。桌面曾显示一张真实表情包。真实账号的类型覆盖、动画和过期资源待测。 |
| 会话首屏与缓存 | 试过会话按 ID 查询、合并列表刷新、优先恢复上次打开的聊天、缓存历史和联系人分页。后续性能验收优先看 Agent 的接收、生成和发送耗时，单独记录桌面体验。 |
| 数据库 v14 | 用真实库的只读副本对比。约 4.6 万条运行记录下，语音和图片任务检查约从 2.1 ms 降到 0.004 ms，媒体修复候选查询约从 0.34 ms 降到 0.08 ms。升级前做了备份，升级后确认索引和数据库版本。数字对应单次本地查询。 |
| 发送排队与回执 | 旧版真实样本最慢约 6.12 s，其中 4.69 s 在 Hub 排队，1.43 s 从开始提交到记下接收回执。后台群资料刷新已改为等网络时让出账号锁。模拟测试验证同一账号两个会话可并行发文字、同一会话保持入队顺序。新版分别记录会话锁、并发名额、账号锁和网络耗时，尚缺系统的真实样本对比。 |
| 桌面辅助功能 | 已做桌面启动、本地 Hub 退出联动、区域截图及媒体显示修补。截图跨屏和权限状态，以及真实语音播放和各类媒体失败场景仍需逐项验收。 |

## 下一轮验收

1. **真实收发。** 用授权测试号分别测私聊和普通群。逐条核对手机会话、Hub 事件和 Agent 的收件记录。覆盖连续消息、同会话顺序、两个会话并行、重启和短时断网恢复。记录重复、漏收和恢复耗时。
2. **备注完整性。** 用已知测试联系人验证新增备注、改名、清空以及重启后仍可按备注查找。核对增量回包、完整刷新和本地读结果。对待处理批次区分群资料、联系人控制字段和查询失败，测批量补齐耗时及对收发的影响。
3. **端到端耗时。** 分别量微信入站到 Hub 提交事件、Hub 到 Agent、Agent 生成回复、回复入队到微信接受。区分空闲、通讯录同步和突发消息，用中位数和 P95 对比，并注明样本量。
4. **媒体。** 补测 Unicode emoji、微信文字表情、静态与动态表情包、图片和语音。记录类型能否识别、文件能否读取、播放或渲染，以及过期时的结果。
5. **运行与权限。** 验证退出窗口、重启系统、休眠唤醒、网络出口与登录恢复。区分微信通信、媒体下载和应用更新流量。运营 Agent 接入先验证会话白名单、去重和人工接管，自动外发仍按项目授权规则执行。

更新日记时记录构建版本、测试账号类型、入口、预期、实际结果和回执。真实账号、备注、消息正文、原始日志和密钥不写入仓库。
